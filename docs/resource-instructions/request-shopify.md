# Shopify Admin GraphQL representation

Apply the shared Shopify Admin API request contract supplied in the Apex envelope, including its centrally configured default version, authenticated shop authority, automatic authentication, permission uncertainty, and knowledge limits. For non-Apex adapters without this context, do not assume a shop or default version.

- Construct an HTTP source with `resourceType: "request"`, `type: "http"`, `method: "POST"`, and `address: "https://<myshopifyDomain>/admin/api/<apiVersion>/graphql.json"`. Use the authenticated shop by default, or the exact explicitly selected external myshopify domain; never change authenticated shop context. Replace the version placeholder using the explicit or centrally configured version before returning source. Preserve an existing explicit version unless an upgrade is requested.
- Set a non-sensitive header parameter `{ "type": "header", "name": "Content-Type", "sensitive": false, "value": "application/json" }`.
- Use one unnamed body parameter: `{ "type": "body", "sensitive": false, "value": "<JSON string>" }`. Its value is serialized JSON containing a GraphQL `query` string and an optional `variables` object. Escape quotes and newlines correctly. GraphQL variables belong inside that body object, not in URL query parameters. Omit `variables` when unnecessary.
- Do not use top-level `url`, `headers`, `body`, `query`, or `variables` fields, an object-valued body parameter, a named body parameter, or a separate GraphQL request type. Preserve assigned identity, required version fields, and established triggers/dependencies; do not invent a trigger or authentication variable.
- For the authenticated shop, rely on automatic authentication by default and omit `X-Shopify-Access-Token`. Preserve existing protected headers on updates.
- For an explicitly requested external store with accepted manual entry, retain one Sensitive `X-Shopify-Access-Token` header with `value: {"mode":"preserve"}`. New protected headers are deferred and unset. State that the user must enter that store's token securely in the request editor before execution. Never emit token values or empty token headers; the destination session token cannot authenticate the external store.
- In Apex, the external target and accepted manual entry must be selected in `constructionContract.externalShopifyTarget` with original customer-message provenance. Constructor cannot invent or change that selection. Missing credentials or unknown grants alone do not block a proposal. Preserve all applicable fixed-operation, reference and schema gates; do not claim authentication or execution verification.
