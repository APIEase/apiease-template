# Saved request invocation and native responses

A Liquid request can call an HTTP helper using a standalone `{% call ... as result %}` tag (no `endcall`). The call argument is a JSON object; `requestId` is the saved request handle. `bodyEmbedded` must be an object, not a JSON string. APIEase serializes it for the internal caller, parses the stored unnamed body parameter, and deep-merges the embedded fields into that body. The returned alias contains the call response, including `status` and `data`; GraphQL payload fields normally live under `result.data.data` and GraphQL errors under `result.data.errors`.

Agree on one calling contract with the caller. To accept a complete GraphQL body, the helper stores an inspectable fixed query in its serialized unnamed body parameter, and the caller supplies `bodyEmbedded.query` and `bodyEmbedded.variables`. To accept variables only, the helper stores a serialized body containing its fixed query, and the caller supplies `bodyEmbedded.variables`. For a complete body, use the same query on both sides so the stored operation remains the operation being proposed and validated. Use the same variable names and types on both sides. Avoid conflicting stored variable defaults: merging objects and arrays is not whole-body replacement. A helper's empty outgoing dependencies are valid when its caller supplies the data; inbound calls do not become dependencies of the helper.
